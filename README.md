# 驱动源 · C 原生版 0.3.4

Windows 10 1809 及以上 x64 的厂商驱动检测、下载与匹配安装工具，使用 C17 和 Win32 系统 API。

本版主列表只管理常用硬件，使用独立的厂商包流程。软件会自动读取整机厂商、型号、System SKU、主板标识、硬件 ID、系统版本和原生架构，无需手工提供型号。

当前可自动下载目录仍为 2 个经核验的乐鑫接口安装包。离线 USB/PCI/数位板资料用于识别，7,238 条联想、戴尔、惠普整机型号/系统记录作为历史来源资料保留；这些数量不代表主列表可下载的驱动数量。常用列表不再提供整个机型的部署包。

版本更新按 `0.3.1 → 0.3.2 → 0.3.3` 推进，逐次补充经核验的目录和功能。

## 使用

0.3.4 将“驱动管理”收窄到显卡（含核显）、物理网卡、声卡、蓝牙、数位板和数控/开发板常用串口设备。ACPI、UART/I²C、WAN 虚拟网卡、蓝牙虚拟服务及系统软件设备只在“本机硬件”完整列表查看。未装驱动、尚未取得设备类别的 PCI 显示/网络/多媒体设备，可通过兼容类代码保留在主列表；常见 USB 串口 ID 和离线识别库中的数位板也保留。

**本次筛选改动没有新增经核验的核显、网卡、声卡或数位板下载包。** 目前仍是原有 2 个乐鑫接口包，不属于一般电脑的主要驱动。界面显示设备或厂商网页，不代表该设备已有可自动下载的安装包。新增厂商载荷的核验被开发环境的 CONNECT 403 域名规则阻止，相关网络配置草稿已保存，需在环境设置保存并发布后继续核验。

1. 完整解压运行包，保留 EXE 旁的 `database` 文件夹，运行 `DriverSource.exe` 自动检测。
2. 常用设备即使已安装驱动也会显示当前状态与版本。没有匹配包时不勾选、不自动下载。双击主列表设备可查看对应厂商的查询入口，网页入口与下载包分别标注。
3. 有单设备包时，勾选后点击“下载并安装”或“仅下载”。只处理勾选项，同一个包只下载一次。默认下载位置为 EXE 所在目录的 `下载`。
4. 下载完成核对 SHA-256 和目录给定大小，ZIP/INF 使用系统 `tar.exe` 解压、PnPUtil 检查签名并匹配安装。当前常用列表不提供整机部署包，避免下载大量不需要的驱动。
5. “本机驱动匹配安装”仅处理仍有完整第三方 DriverStore 包的常用设备。Windows 可能保留当前同版本，处理成功不能等同于文件已重写。默认先备份，详情见独立 `LocalMatch-{GUID}/install.log`。
6. 处理完成后点击“重新检测并匹配”刷新版本。没有下载源时，可查看厂商入口或使用本机包；软件不会通过 Windows Update 自动搜索。

下载包保存在独立的 `Vendor-{GUID}` 目录，包含已下载文件及相关 `extract.log`、`install.log`。失败的 `.part` 文件会清理。

## 已安装驱动与版本建议

驱动状态、当前版本、提供商、日期和 INF 来自 Windows 本机设备与驱动登记信息，读取不依赖下载目录。单设备包已经匹配时，仅在提供商明确相同且双方版本都是有效数字版本时进行比较：版本较新显示“可更新”，相同显示“同版本，可重新匹配安装”，较旧显示“本机版本较新，建议保留”。来源不同或版本不明确时显示“版本待核对”。整机包中包含多个设备驱动，不使用整机包发布日期代替单设备版本。

没有下载源时也显示已安装版本。完整第三方包仍在本机 DriverStore 时，可勾选后点击“本机驱动匹配安装”。同一个已安装 INF 对应多个设备时只提交一次。操作前重新核对设备当前 INF 和版本；驱动已被其他程序更改时要求重新检测。操作使用 PnPUtil 的正常驱动匹配规则，不强制降级或覆盖已安装的最佳驱动，返回成功表示系统工具已处理请求，不能据此断言文件已经重写。

本机匹配安装默认先备份第三方驱动，日志保存到所选下载目录下独立的 `LocalMatch-{GUID}/install.log`。当前版本仅为可解析且仍存在于本机 DriverStore 的 `oem数字.inf` 第三方包开放此操作。Windows 自带 INF 仍正常显示版本，安装操作由系统维护。

## 厂商安装包目录

运行时读取 `database/vendor-packages.tsv`。包记录包含标题、来源厂商、版本、完整硬件 ID、HTTPS 下载地址、SHA-256、文件大小、最低系统内部版本、架构和目标 INF。

单设备目录支持 x64 ZIP/INF 包，使用 Windows 自带 `tar.exe` 解压和 `pnputil.exe` 匹配安装。底层仍保留历史 CAB 工具支持，常用列表不添加整机包。单设备包仅按设备的硬件 ID 精确命中，不使用通用兼容 ID 或仅按厂商 VID 匹配。设备逐项显示，相同包被多个设备命中时下载只执行一次。ARM64 不使用 x64 包。

已核验的包来源为 [Espressif 官方发布](https://github.com/espressif/esp-win-usb-drivers/releases)。包校验、INF 原始 ID、版本和文件列表见 [来源记录](database/vendor-packages-provenance.json)。国内访问速度与具体设备安装效果需实测。

历史整机快照、上游提交、源文件哈希和 GPL-3.0 许可见 [整机目录来源](database/oem-snapshots/README.md)。索引维护命令仍可运行 `python scripts/build_oem_catalog.py`，应用及 C 编译无需 Python；常用列表不使用整机包作为单设备下载项。

普通厂商支持网页仍在“驱动来源”中提供查询。来源入口的 HTTP 状态只能反映入口连通性。当前云环境的域名权限阻止访问 WCH、联想等站点，直接厂商载荷下载仍需逐项核验；历史整机目录只作为识别来源资料，不作为常用设备安装包。

维护者可以扩充 TSV，重启软件后生效，不需要重新编译 EXE。新增记录前必须核验真实包、x64 INF、完整硬件 ID、签名目录、版本和系统适用范围。共享 ID 的机型需要额外条件，现有格式不支持时暂不加入自动目录。例如三个 ESP 调试板共享 FTDI `VID_0403&PID_6010&MI_00`，本版未将其当作通用 FTDI 驱动自动匹配。

可选 Python 维护检查会下载目录中的原始包并核对哈希、大小、INF ID 和文件路径，不执行安装，也不修改目录：

```sh
python scripts/verify_vendor_packages.py
```

## 离线硬件识别库

本版打包 USB IDs、PCI IDs 和数位板机型资料，启动后可离线识别硬件标识并提供来源建议。

| 数据 | 数量 |
| --- | --- |
| USB 厂商 / 产品 | 3,427 / 20,537 |
| PCI 厂商 / 设备 / 子系统 | 2,526 / 21,915 / 18,163 |
| 数位板品牌分组 / 机型名称 / 标识映射 | 28 / 363 / 428 |

数位板资料包括 Wacom、Huion、XP-Pen、UGEE、GAOMON、VEIKK、Xencelabs、Parblo、Artisul、BOSTO 等。USB/PCI 资料还覆盖显卡、网卡、蓝牙、声卡、打印机、扫描仪、摄像头、键鼠、存储控制器、USB 串口等硬件的已知标识。

“本机硬件”会显示离线识别结果、设备类别、识别依据及来源建议。选择设备后点击“查看设备来源建议”，来源列表会按已知厂商或机型候选筛选。可用“显示全部来源”恢复完整列表，连通性检查针对当前列表执行。

识别会检查设备报告的多个硬件 ID 和兼容 ID，并优先保留更具体的 PCI 子系统结果。共享 VID/PID 的数位板显示候选数量和核对提示。设备标识命中用于确认候选与寻找来源，具体驱动仍需核对系统版本、架构及厂商支持条件。

USB 数据快照为 2026.06.26，PCI 数据快照为 2026.11.22。来源提交、原始配置、校验值和许可说明见 [database/README.md](database/README.md)。

构建脚本会自动将识别库复制到 EXE 输出目录。应用的编译与运行使用 C 和现有数据文件，维护者可以用可选脚本重建数位板索引。

## 进度、取消与诊断

直接按收到的下载字节统计百分比、已下载大小和估算速度。每半秒计算速度，短小文件可能在形成有效速度采样前下载完成。连接、校验、解压和安装有各自的等待提示。

取消下载会在当前网络请求返回后生效，单次请求设置了超时；取消解压可以终止当前解压进程。PnPUtil 安装和 DISM 备份会等待当前系统操作结束，以保留真实结果。任务取消后不会再开始下一项安装。

“系统诊断”展示整机型号、提权状态、系统版本、架构、主板标识和厂商目录加载结果。日志保存在软件目录 `logs/DriverSource.log`，包含本机设备名称、硬件 ID、驱动版本、匹配状态及处理结果。硬件信息保存在本机，不上传硬件报告；下载请求只访问所选包的发布地址。

## 驱动备份与导入

默认备份位置为 EXE 所在目录下的 `驱动备份`。在“驱动备份”页可更改位置、手动备份、打开备份目录或导入已有备份。目录写入失败时，可选择具有写入权限的位置。

- 每次备份使用 Windows DISM 导出当前系统的第三方驱动包，生成独立的 `Backup-时间-GUID` 目录。
- 成功备份包含 `backup-complete.txt` 标记、驱动包及日志。失败任务保留在 `.partial` 目录内，便于查看 `output.log` 和 `dism.log`。
- 默认在一批驱动安装前备份一次。备份失败会暂停后续安装，可排查后重试，也可按需要调整“安装前备份现有驱动”选项。
- 导入时选择完整的 `Backup-时间-GUID` 文件夹。程序使用 Windows PnPUtil 导入 INF，并为兼容设备安装匹配项，处理结果保存在备份根目录的 `Restore-时间-GUID.log`。
- 备份导入遵循 Windows 的驱动排名规则。需要降级版本时，可在设备管理器中使用“回退驱动程序”或手动选择备份中的适配 INF。
- 备份内容为第三方驱动包。Windows 自带驱动由系统维护，厂商附带应用可从相应安装包重新安装。
- 导出和导入由系统工具完成。期间的取消和关闭请求会在当前系统操作结束后生效，已完成的备份会保留。

## 自行编译

程序链接 Windows 系统库。编译器可以沿用现有工具链，无需安装额外的运行库或包管理器。

### 一键编译

自行编译请下载 `DriverSource-Source-and-Build.zip`，完整解压后双击根目录的 `build-windows.bat`。这个包包含 C 源码、数据库、编译脚本和已编译的根目录 EXE；`DriverSource-Windows-x64.zip` 仅用于直接运行，不包含完整源码。C 编译器需预先安装或放入便携工具链目录。

0.3.3 的入口立即显示启动提示，每个 C 文件显示独立进度。工具运行期间每 5 秒显示等待提示，每条命令默认最多等待 300 秒，超时仅停止这次启动的工具进程树。全过程记录到 `build/build.log`，双击运行结束后窗口保留，按键关闭。脚本使用 Windows 10/11 自带的 Windows PowerShell 5.1；不会安装编译器，也不修改持久执行策略。

只检查环境可运行 `build-windows.bat --diagnose --no-pause`；自动化可添加 `--no-pause`。显式指定 `mingw` 或 `msvc` 时默认不暂停。若仍编译失败，请查看日志中最后的“失败步骤”和第一条编译错误，不要只依据黑窗判断是否卡住。较慢的电脑可在 PowerShell 中运行 `./scripts/build-windows.ps1 -CommandTimeoutSeconds 900` 增加单条命令等待时间。


在 Windows 运行：

```bat
build-windows.bat
```

脚本优先识别 MinGW-w64 GCC，随后尝试 MSVC。输出为 `dist\DriverSource.exe`。

- **MinGW-w64** — 使用支持 C17 的 64 位 GCC，将其 `bin` 加入 PATH。也可将工具链放入项目内 `tools\mingw64` 或 `mingw64` 目录。需包含 GCC 和 windres。
- **MSVC** — 安装 Visual Studio 2022 或 Build Tools 的 MSVC 与 Windows SDK 组件。脚本通过 vswhere 自动初始化编译环境，也可从 x64 Native Tools 命令提示符运行。

可以明确指定编译器：

```bat
build-windows.bat mingw
build-windows.bat msvc
```

### IDE 与 CMake

支持 CMake 3.20+。可用支持 CMake 的 IDE 打开项目。Visual Studio 2022 的命令行构建方式为：

```bat
cmake -S . -B build-vs -G "Visual Studio 17 2022" -A x64
cmake --build build-vs --config Release
```

输出为 `build-vs\Release\DriverSource.exe`。

在已配置 MinGW-w64 和 Ninja 的命令行中，也可使用：

```bat
cmake -S . -B build-gcc -G Ninja -DCMAKE_C_COMPILER=gcc -DCMAKE_RC_COMPILER=windres
cmake --build build-gcc
```

输出为 `build-gcc\DriverSource.exe`。

## 验证范围

新增常用硬件筛选检查覆盖真实 PCI/USB 显卡、网卡、音频、蓝牙、数位板和串口，排除系统与虚拟设备，并验证未安装驱动时的 PCI 兼容类代码。界面检查验证主列表双击可进入对应厂商来源，且不会因此启用下载按钮。

GitHub Actions 使用 MinGW-w64 和 MSVC 编译，并验证硬件识别、速度统计、厂商包精确匹配、系统架构和版本过滤、SHA-256、取消和篡改拒绝。Windows 下载测试会从厂商官方 GitHub 发布中下载两个实际包并解压，不执行驱动安装。

新增版本数值比较、无下载源已安装设备、只读 Windows 驱动登记读取和主列表零匹配场景检查。窗口测试验证已安装设备在没有目录来源时仍显示当前版本，并区分下载和本机匹配安装按钮；这些测试不会安装驱动。本机匹配安装的实际效果仍需实机验证。

原生窗口和设备枚举检查：

```bat
DriverSource.exe --self-test
DriverSource.exe --smoke-test
```

厂商目录匹配可在普通 C 环境独立验证：

```sh
gcc -std=c17 -Wall -Wextra -Werror tests/test_vendor_catalog.c native/vendor_catalog.c -o test_vendor_catalog
./test_vendor_catalog
```

新增整机目录测试验证厂商、型号代码、SKU、系统发行版本、架构隔离和真实快照加载。CAB 解压测试使用 Windows makecab 生成的无害测试包，不执行驱动安装。

实际整机包下载、硬件安装、版本替换、国内网络速度、DISM 备份及恢复需 Windows 实机验证。完整常用驱动库仍需继续接入并核验更多厂商安装包。
